# NTFS for Mac Lightweight — UI 指南

## 1. 设计目标

界面只帮助用户回答三个问题：

1. 这块磁盘现在是什么状态？
2. 我现在能做什么？
3. 如果不能做，下一步该去哪处理？

第一版采用 C 版“磁盘列表 + 状态详情”的原生 macOS 结构。Finder 负责文件浏览，应用只负责状态、写入切换、安全推出、首次设置与诊断。

已确认的设计决定：

- 菜单栏保留常驻入口，但不承载另一套磁盘操作界面。
- 正式实现只保留 C 版；A/B 仅留在一次性原型中作为设计来源，不把变体切换器带入产品。
- 主窗口一次只展开一个磁盘或一个设置分类，避免多个卡片同时争夺主操作。

## 2. 信息架构

### 菜单栏入口

菜单栏只展示简短状态并打开主窗口，不提供“启用写入”或“安全推出”，避免和主窗口形成两个可能不同步的操作入口：

```text
NTFS 轻量助手

检测到 2 块 NTFS 磁盘
[打开 NTFS 轻量助手]
```

没有磁盘、设置未完成或操作进行中时，菜单栏仍只用文字摘要状态；完整原因和下一步统一进入主窗口查看。

### C 版主窗口

建议宽度 720–820 pt，使用主从结构：

- 左侧 200–220 pt：磁盘列表；进入设置时改为“运行环境、诊断摘要”等文字分类。
- 右侧：选中项名称、设备摘要、状态、准确原因、必要事实和动作。
- 同一时刻只显示一个主操作；次要操作排在主操作后，不使用图标隐藏含义。
- 多分区磁盘按运行期“物理磁盘 1、2…”分组，但动作仍绑定完整卷实例，并明确安全推出会作用于
  整块物理盘；界面不把 BSD 名、UUID 或原始挂载路径当作设备摘要。
- 多卷物理盘的每个 sibling 使用确定的“卷 1、2… · 原卷名”本地展示标题；唯一前缀避免同名
  卷以及用户卷名与生成文字发生碰撞。单卷物理盘保留原卷名。序号只用于本次展示与辅助功能
  区分，不是分区号、持久身份或授权依据。不同卷的公告事件必须绑定完整选择身份，不能只用
  可能相同的朗读正文判断是否发生切换。
- 所有卷选择控件的辅助功能标签都包含“物理磁盘 N，卷标题”；不能依赖分组标题恰好被重复
  朗读来区分不同物理盘上的同名卷，也不能把 UUID、BSD 名或路径加入标签。
- 保留选择与展示选择必须分开：同一订阅的 scanning 可以记住暂时缺失的卷，但 Picker、侧栏、
  详情和公告只能消费当前 dashboard 中实际存在的展示选择，缺项时统一回概览。卷重新出现后
  可以恢复展示选择，但不能主动抢回已经回落到概览的键盘焦点。
- 宽版中已聚焦的卷项消失时，焦点回到当前展示项；窄版 Picker 只更新选择并保留焦点。
  wide/compact 切换只在导航区原本持有焦点时把焦点转到 Picker 或当前展示项，不能从标题、
  详情、“重新读取”或其他控件抢夺焦点。

在 560 pt 以下，左侧列表折叠到详情上方；在 320 pt 验收宽度下检查项、状态词和按钮允许换行，不产生横向滚动。

### 首次设置

首次设置复用 C 版窗口：左侧选中“运行环境”，右侧使用逐项检查，不使用模糊的“安装失败”：

```text
首次设置

已满足  macOS 15.4 或更高版本
已满足  Apple Silicon
待处理  确认批准的 macFUSE 版本与签名身份
待处理  启用 File System Extension
待处理  确认受支持的 NTFS-3G

[打开 macFUSE 安装说明]
```

状态词必须使用文字；图形只能作为辅助。

“继续设置”只打开同一主窗口内针对首个待处理项的说明；它不静默下载依赖、不修改系统设置，也不把外部网页打开等同于问题已解决。用户完成手动步骤后，再使用“重新检查”。

## 3. 状态与主操作

同一时刻只展示一个主操作。处理中禁用重复操作，但保持取消菜单关闭不影响后台任务。

下表的 24 个 `VolumeState` 描述 Gate 4 通过后的 mutation UI。当前正式只读 App 还必须展示
独立的 `ReadOnlyVolumeCandidate`：它可以报告访问事实，但角色用途未确认时没有任何磁盘变更动作。

| 领域状态 | 标题 | 说明 | 主操作 | 次要操作 |
|---|---|---|---|---|
| 未检测到磁盘 | 没有检测到 NTFS 磁盘 | 连接外置 NTFS 磁盘后会自动显示。 | 无 | 设置与诊断 |
| 设置未完成 | 首次设置未完成 | 列出具体缺失项。 | 继续设置 | 复制诊断摘要 |
| unknown-role candidate | 用途未确认 | 卷身份与当前访问状态已核对，但系统不能证明它是数据卷还是 Windows 系统卷。 | 无 | 无（诊断为独立入口） |
| `readOnlyReady` | 当前只读 | 磁盘健康，可以手动启用写入。 | 启用写入 | 在访达中打开、安全推出 |
| `unmountedReady` | 当前未挂载 | 磁盘已识别，重新检查后可手动启用写入。 | 启用写入 | 安全推出 |

| `mountingWrite` | 正在启用写入 | 正在通过 FSKit 挂载。 | 无 | 无 |

| `writeVerificationFailed` | 未能确认可写 | 没有把命令成功当作写入成功。 | 查看详情 | 安全推出 |
| `writeOperationFailed` | 未能启用写入 | 显示失败阶段、原因和重新检测建议。 | 查看处理方法 | 安全推出、复制诊断摘要 |

| `ejectMutationQuiescencePending` | 正在等待推出操作停止 | 整盘卸载或推出结果不确定；进程退出前保持整盘锁定。 | 无 | 无 |
| `awaitingEjectMutationReconciliation` | 正在核对整块物理盘 | 进程已退出，仍需完整 sibling 与物理盘事实才能解除锁定。 | 无 | 无 |
| `unmountingForEject` | 正在同步并卸载 | 正在标准卸载这块物理盘的所有分区。 | 无 | 无 |
| `awaitingUnmountVerification` | 正在检查所有分区 | 确认没有同盘分区仍在使用。 | 无 | 无 |
| `ejecting` | 正在推出磁盘 | 请保持磁盘连接。 | 无 | 无 |

不要使用下列乐观文案：

- “挂载命令已完成，所以可以写入”
- “推出命令已完成，所以可以拔出”
- “大概已经安全”

## 4. 写入阻止文案

| 原因 | 标题 | 用户说明 | 可执行建议 |
|---|---|---|---|
| Windows 休眠 | Windows 仍处于休眠状态 | 此时写入可能破坏 Windows 保存的会话或文件系统。 | 回 Windows 关闭快速启动并完整关机，然后重新连接磁盘。 |
| dirty 文件系统 | 磁盘未干净卸载 | 磁盘需要 Windows 完整检查，应用不会自动清除日志。 | 在 Windows 中运行 `chkdsk`，确认无错误后重新连接。 |
| 健康状态未知 | 无法确认磁盘安全 | 缺少足够证据，因此保持只读。 | 查看诊断，排除权限或检测工具问题。 |
| 内部磁盘 | 不支持内部 NTFS 写入 | 个人轻量版只处理外置数据盘。 | 保持只读。 |
| 受保护卷 | 不支持此卷写入 | 系统证据表明它超出个人版安全范围；其中可能包括内部或 Windows 系统卷。 | 保持只读；若需处理 Windows 系统卷，请进入 Windows。 |
| 介质已变化 | 磁盘已重新连接 | 之前的操作证据已经失效。 | 等待重新检测后再次操作。 |
| 后端不符 | 未使用安全后端 | 当前挂载不是预期的 FSKit 路径。 | 先安全推出，再检查设置。 |

危险状态不得出现“仍然继续”或隐藏的 Option 键绕过入口。

## 5. 交互规则

- “启用写入”每次都由用户明确点击；MVP 不自动切换为可写。首次进入当前连接的写入请求前，
  用户还必须提交固定语义“所选卷是数据卷且不是 Windows 启动/系统卷”的声明。
- 声明不能被记住、自动确认或显示成系统检测结果；重插、应用重启、睡醒重订阅、拓扑变化和
  一次消费都会使其失效。candidate 自身始终没有 mutation 动作；声明与 fresh 事实只能进入
  本次写入资格核对，整盘推出需要独立的可信 snapshot 与正式规则。
- 点击后立即显示当前阶段，但不提前显示最终成功。
- 重复点击不创建第二个操作。
- 同一物理盘上的多个分区共享一个操作锁。
- 一个 sibling 持有整盘租约时，其他仍连接的 sibling 显示“同盘操作进行中”和“请勿读写或断开磁盘”，不拼接旧状态的操作建议，也不提供任何动作；已撤销的 sibling 直接显示“磁盘已断开”。
- 安全推出永远作用于整块物理盘，并清楚提示会卸载同盘所有分区。
- 因休眠、dirty 或健康状态未知而禁止写入时，只有角色已可信为 data 的 snapshot 仍可安全推出；
  用途 unknown candidate 不可推出。
- 内部、其他 `protected` 卷，以及同盘存在受保护 sibling 时，不显示或执行整盘推出。
- 最终预检发现新的 dirty、休眠、重挂载或受保护 sibling 时，保留具体原因，不退化为笼统“未知错误”。
- 写入或推出变更超时、取消后，不显示安全推出或重试；整盘卸载或最终推出明确失败时同样先显示“正在核对整块物理盘”，正常检查若事实不完整也保持该状态，只有完整卷或整盘观测后才解除整盘锁。
- 整盘 absence 验证后，发起卷保留“已验证可以拔出”，其他 sibling 显示“磁盘已断开”；重复移除事件不撤销已验证结果。
- 租约释放前，当前 operation 接纳的完整 present 事实必须同步所有 sibling；一旦同代介质已收到移除事件，任何迟到 `present`（包括相同 operation ID）都不得把“磁盘已断开”恢复成可写、只读或可重试，只能继续显示核对中并重新读取。
- 设备忙时不强制卸载，也不自动关闭其他应用。
- 应用重启后从系统重新读取状态，不显示上次缓存的“可写”或“可拔出”。
- 磁盘重新插入会创建新的介质代次；旧代次的延迟回调不得提供操作入口。
- `mediaInvalidated` 不能基于旧磁盘快照提供“再试一次”或“安全推出”；必须等待 inventory 重建。

## 6. 错误详情

错误卡片按固定顺序展示：

```text
未能安全推出

原因
“ARCHIVE” 仍在被使用。

你可以这样做
关闭正在访问该磁盘的访达窗口或应用，然后重试。

[再试一次]  [复制诊断摘要]
```

面向用户的错误不能只展示退出码。技术详情放在折叠区域：

- 操作阶段
- 本次运行内的物理盘与卷数字别名
- 介质代次
- 观察到的挂载状态
- 后端与版本
- 固定错误类别和数值退出状态

诊断摘要采用固定字段白名单，不接收自由文本。它不得包含卷标、用户名、BSD 名、磁盘或卷 UUID、任何路径、文件名或任何 stderr 文本；界面也不能提供“保留原名”或“仅脱敏后保留”的绕过选项。

## 7. 视觉与可访问性

- 所有路径、状态与结果都用文字表达；不要依赖图标或颜色。
- 正常状态使用系统标签色，警告使用黄色语义色，阻止或失败使用红色语义色，但文字含义必须完整。
- 主按钮使用系统强调色，不用自定义渐变或高饱和装饰。
- 支持浅色、深色、高对比度和“减少动态效果”。
- 正文不小于 13 pt；状态标题建议 17 pt semibold。
- VoiceOver 顺序：磁盘名称 → 设备摘要 → 状态 → 原因 → 主操作 → 次要操作。
- 进度状态使用不确定进度条并朗读阶段变化；不要高频刷新文本。

# 诊断只持久化私有、有界、可验证的结构化快照

正式本地应用可以跨重启保留最近的脱敏诊断，但唯一可落盘内容是
`DiagnosticSnapshot` 的 canonical JSON。快照沿用封闭字段白名单和运行期匿名别名，写入
用户 Application Support 下的专用目录；文件以原子替换和 `0600` 权限保存。读取前核对
目录与文件不是符号链接、owner 和权限可信、类型为普通文件、字节数有界、schema 已知、
重新编码后字节完全一致且时间未过期或来自未来。任一条件不成立都忽略旧快照，不尝试
修复或宽松解析。

每次保存还必须携带归档当前签发的 generation。`clear` 在处理文件系统前先轮换 generation；
因此清空前开始、清空后才完成的保存会得到 `superseded`，不能让旧快照复活。新的 generation
仍可正常保存，且 UI 不把被取代的旧保存误报为清空失败。

持久化诊断只用于解释上次运行，不恢复磁盘身份、协调器租约、operation ID、成功状态或
任何可授权变更的系统事实。应用版本和 build 从本次 bundle 的严格三段版本元数据读取，
不在源码中维护第二份版本常量。

## Considered Options

- 保存自由文本日志、命令行或 stderr：拒绝，因为无法证明其中不含用户名、卷标、路径、
  UUID、BSD 名或第三方工具输出。
- 只保留内存诊断：拒绝，因为应用异常退出后无法解释最后一次只读观察和设置失败。
- 宽松读取旧 schema 或损坏 JSON：拒绝，因为未知字段和重复键会让隐私与语义边界失效。
- 从持久化诊断恢复运行状态：拒绝，因为历史记录不是当前 Disk Arbitration 或 mount table
  事实，也不能证明当前介质实例身份。
- 清空时只删除文件、不轮换保存资格：拒绝，因为并发中的旧保存可以在删除后重新创建快照。

## Consequences

- 应用重启后能展示最近一次仍在保留期内的脱敏快照，同时保持零原始磁盘标识。
- 旧文件被修改、权限放宽、替换为链接、超限、过期或 schema 漂移时，应用只显示固定的
  完整性失败说明并从新的只读事实开始。
- 清空与异步保存以归档 generation 排序；旧 generation 被拒绝属于正常并发收敛，不产生
  虚假的用户错误。
- 诊断模型新增字段或升级 schema 时，必须同步更新字节上限、隐私检查、迁移决策和行为
  检查；默认行为仍是不读取未知 schema。
- 本 ADR 不构成 Gate 5 的供应链、签名、公证或个人使用验证证据。

# 使用结构化、一次性 helper 协议

未来需要权限的磁盘变更只能通过版本化结构协议进入 helper。协议不接受命令文本、
参数数组、路径、挂载选项或标准错误，只接受完整介质实例、一次性操作 ID 与四种固定
动作：可写挂载卷、标准卸载卷、标准卸载整盘和标准推出整盘。helper 进程在解码后先
原子消费操作 ID，只有首次请求可继续；容量耗尽时拒绝新请求，不淘汰旧 ID。

进程对外只暴露一个接收原始消息的原子准入入口。该入口按顺序执行 4 KiB 字节上限、
严格 JSON 与嵌套重复键拒绝、schema/身份/action 核对和 operation ID 消费；解码器与
重放集合不能被外部拆开调用。成功结果由协议模块内部构造，调用方不能伪造“已准入”。

这条边界只定义消息，不授权安装 helper、建立 XPC 连接或执行磁盘变更。任何请求仍需
先由 `VolumeCoordinator` 取得整盘租约、读取最新完整系统证据并消费一次性变更意图。
响应仅包含协议版本、固定数值结果码和数值退出状态；命令成功仍不能替代挂载表或
Disk Arbitration 的最终系统事实复核。

## Considered Options

- 让 UI 或主应用向 helper 发送 shell 命令与参数：拒绝，因为这会把最小权限 helper
  变成通用命令执行器，也让挂载安全策略可被调用方绕过。
- 只传 BSD 名称：拒绝，因为 BSD 名可在拔插后复用，无法绑定原介质代次。
- 重复操作 ID 时保持幂等并再次执行：拒绝，因为卸载、挂载和推出的外部状态可能已经
  改变；重放必须回到协调器重新读取系统事实。
- helper 自己根据缓存决定目标：拒绝，因为缓存不是当前系统证据，且会形成第二套领域
  状态机。

## Consequences

- helper 与主应用之间的接口小而可审计，未知 schema、动作、字段、身份和超限消息均
  失败关闭。
- 准入检查与 operation ID 消费属于同一个 actor 隔离的原子步骤，不存在调用方先验证、
  再绕过重放消费直接执行的两阶段接口。
- helper 内部仍必须把固定动作编译成固定平台 API 或安全调用，并在执行前重新核对目标；
  本 ADR 不批准任何具体执行器。
- helper 重启会清空进程期重放集合，因此主应用不能在断线后自动重发旧操作；必须让
  协调器从新的系统事实重新开始。
- 加入 XPC、签名、安装或真实执行前，需要新的 ADR 与 Gate 2 磁盘镜像证据。

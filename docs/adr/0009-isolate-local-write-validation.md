# 把已授权的 macOS 写入实验与正式应用分开

2026-09-09 用户接受安装 macFUSE 5.4.0 候选，并明确将 Windows 复核后置，要求先完成
macOS 侧功能与文件操作闭环。采用独立、显式启动的本地实验工具执行一次性镜像和已授权
可牺牲 U 盘测试，因为等待所有写入 Gate 通过才允许任何实验会阻断获取 Gate 证据，而直接
放开正式应用会混淆个人实验授权与经过验证的产品能力。

## Considered Options

- 保持所有执行入口关闭直到 Windows 复核：不能满足用户已明确调整的开发顺序。
- 直接把未批准的依赖接入正式 UI：拒绝，因为会让未知用途、签名策略和操作资格绕过既有边界。
- 独立实验工具：采用。允许验证真实文件语义并保留证据，正式应用仍保持只读依赖图。

## Consequences

- 该授权只覆盖当前一次性镜像和用户指定的可牺牲外置盘。工具必须拒绝内部盘、未知身份、
  符号链接、只读或来源不匹配的挂载，不能以运行权限代替目标核对。
- 固定 `rw,no_def_opts,backend=fskit,norecover`，显式关闭上游跨用户访问与非空挂载点默认选项；不使用强制卸载、恢复写入、删除休眠文件、内核后端或降低
  系统安全性。macFUSE 安装与系统认证采用系统原有流程。
- 实验代码位于独立 `scripts/write-validation/`，不进入正式 Swift 应用依赖图，也不新增
  Swift `Process` 调用。操作使用固定语义，未知命令/字段/路径不被解释成 shell 代码。
- 测试数据只位于独占创建、绑定卷和运行身份的目录；读回、覆盖、追加、重命名、删除和
  清理均核对结果。失败保留实际状态，不能将异常当作文件不存在或将进程退出当作已卸载。
- macOS 当次检查、重新挂载持久化检查和 Windows 复核分别记录。Windows 未验证不能获得
  `roundTripVerified`，本轮本机成功也不会自动宣布 Gate 1–5 通过。
- 正式 helper/XPC、系统启动执行器和产品 UI 仍需原有领域接口与独立验证；本实验不是通用
  提权入口，也不批准对其他磁盘开放写入。

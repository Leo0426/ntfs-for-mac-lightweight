# NTFS for Mac Lightweight — MVP PRD

本文定义产品范围与验收意图。Gate 的编号、前置关系和当前状态只引用[分阶段实施计划](../engineering/implementation-plan.md)，本文不另行编号，也不据纯逻辑检查或本机只读 smoke test 宣称 Gate 通过。

## 问题陈述

个人用户偶尔需要在 Mac 与 Windows 间使用已有 NTFS 外置磁盘。macOS 默认通常只能读取 NTFS；商用工具虽能透明读写，但附带格式化、修复、内核扩展等超出个人需求的能力，也扩大了安装复杂度与数据风险。

本项目只解决一件事：让用户先看清外置 NTFS 卷的只读事实，在当前连接中显式确认它是数据卷
且不是 Windows 启动/系统卷，再经 fresh 系统证据核对后手动切换为可写，并能可靠、安全地推出。

## MVP 目标

在 macOS 15.4+ 的 Apple Silicon Mac 上，用户可以完成：

`检测外接 NTFS 卷 → 显示用途未确认候选 → 当前连接一次性声明 → fresh 安全复核 → 手动启用写入 → 验证真实可写状态 → 在访达中使用 → 标准安全推出 → 验证磁盘已移除`

MVP 成立需同时满足：

- 健康外置 NTFS 卷能稳定完成上述流程。
- 危险或无法确认安全的卷始终拒绝写入。
- UI 不根据命令成功直接宣称“可写”或“可以拔出”，必须以新的系统观察结果复核。
- 在可牺牲磁盘上通过 macOS 写入、标准卸载、Windows `chkdsk` 与内容哈希一致性验证。

## 目标用户

- 主要用户：开发者本人，需要偶尔读写 Windows NTFS 外置硬盘、SSD 或 U 盘。
- 次要用户：暂无；第一阶段不面向公开分发或企业部署。

## 解决方案

提供一个文字状态优先的原生 macOS 应用。UI 已选择 C 版“磁盘列表 + 状态详情”方向：

- 菜单栏只承担常驻状态和打开主窗口，不复制写入或推出操作入口。
- 主窗口左侧显示检测到的磁盘或设置分类，右侧只展开当前选择的状态、风险原因和唯一主操作。
- 首次设置、危险状态、Windows 处理指引、环境检查和脱敏诊断均复用同一主窗口，不再维护另一套详情操作界面。
- 窄窗口下左侧列表折叠到内容上方；状态和动作语义保持不变。
- Finder 仍是文件操作界面，应用不自建文件管理器。
- 默认技术底座为经 Gate 2 批准的精确 NTFS-3G 版本与产物摘要，加经精确身份核对的
  macFUSE FSKit 后端；当前 2026.7.7 只是一项未批准候选，不能自动接受更新版本。

## 用户故事

1. 作为个人用户，我想看到当前外接 NTFS 卷是只读、处理中还是可写，以便判断能否使用。
2. 作为个人用户，我想明确看到“用途未确认”，并在每次连接中确认所选卷是数据卷而不是
   Windows 启动/系统卷，以免应用把外置位置误当成安全角色。
3. 作为个人用户，我想手动点击“启用写入”，以便在确认安全后通过 Finder 修改文件。
4. 作为个人用户，我想在休眠、脏卷或健康状态未知时看到明确原因和 Windows 处理方法，以免误操作损坏数据。
5. 作为个人用户，我想通过“安全推出”完成标准卸载和整盘推出，以便知道何时可以拔出设备。
6. 作为维护者，我想复制脱敏诊断摘要，以便区分缺失依赖、冲突驱动、权限、忙碌设备和引擎失败。

## 范围

### 范围内

- 系统层核对外接 NTFS 卷的卷名、来源设备、挂载点和只读、可写、未挂载状态；正式 UI 只展示
  卷名、运行期物理盘序号、用途确认状态和访问状态；多卷物理盘的每个 sibling 另显示不持久化
  的本地同盘卷序号，保证标题唯一。界面不显示可被重插复用的 BSD 名、UUID 或原始路径，展示
  序号也不参与授权判断。
- 其余事实完整但角色 unknown 的外置 NTFS 只显示为 candidate；没有写入或整盘推出资格。
- 当前连接固定语义声明与 fresh candidate、精确 sibling 拓扑完全一致后，才进入健康卷的手动
  “启用写入”流程；声明不持久化，也不成为系统证据。
- 写入前重新检查卷身份、物理磁盘、介质代次、健康状态和实际卸载状态。
- 固定安全挂载策略：FSKit 后端、禁用日志恢复、不向其他用户开放。
- 挂载后验证目标卷、介质代次、读写标志、后端和 `/Volumes` 挂载点。
- 标准整盘卸载与推出；检查所有同盘分区均已卸载。
- 内部或其他 `protected` 卷，以及含受保护 sibling 的物理盘明确拒绝整盘推出；生产系统层不
  按卷名声称精确识别 Boot Camp。
- 只有确认物理磁盘已从系统中消失后显示“可以拔出”。
- 首次设置检查：系统版本、架构、macFUSE、NTFS-3G、后端、权限和冲突驱动。
- 结构化错误、用户可执行的处理建议和脱敏诊断摘要。
- 失败时保留 macOS 原生只读访问作为兜底。

### 范围外

- NTFS 格式化、分区、擦除、文件系统检查或修复。
- 强制卸载、强制推出、自动终止占用磁盘的应用。
- 删除 Windows 休眠文件、使用 `remove_hiberfile`、自动清日志或恢复脏卷。
- 内部或其他受保护 NTFS 卷写入，包括用户已知的 Boot Camp 系统卷。
- BitLocker、磁盘加密和数据恢复。
- 自动可写挂载；MVP 每次由用户明确发起。
- 内核扩展后端、降低启动安全性、关闭 SIP 或替换系统文件。
- 自建文件管理器、性能排行榜和公开分发安装包。

## UI 状态

主界面采用已选定的 C 版“左侧列表 + 右侧详情”。一次只允许一个选中项和一个主操作；颜色和图标仅辅助，所有状态必须有文字：

- 没有检测到 NTFS 磁盘
- 首次设置未完成
- 用途未确认：显示当前访问事实，不提供启用写入或安全推出
- 当前只读，可启用写入
- 正在卸载系统只读卷
- 正在重新检查磁盘安全状态
- 正在启用写入
- 正在验证实际挂载状态
- 正在等待超时或取消的系统操作真正停止
- 正在用新的完整系统事实核对操作结果
- 正在核对超时或取消后的整块物理盘
- 已验证可写
- 写入已阻止：Windows 休眠、卷不干净、健康状态未知、受保护卷或介质已变化
- 正在同步并推出
- 仍有卷或应用正在使用
- 推出失败，磁盘仍连接
- 已验证可以拔出

危险状态应替换主操作，不显示“仍可继续写入”的入口。

## 实现决策

- 主要 Module：
  - `VolumeCoordinator`：按物理磁盘串行协调状态机。
  - `MountEngine`：隐藏 NTFS-3G、macFUSE 和挂载参数。
  - `DiskObserver`：提供卷、挂载及整盘存在性的系统事实。
  - `SetupChecker`：检查依赖、权限、版本和冲突。
  - `Diagnostics`：只输出固定字段白名单，不接收需要事后脱敏的自由文本。
  - C 版主窗口：当前只读部分只消费 `ReadOnlyDashboardPresentation`；Gate 4 的 mutation 部分
    才消费由 `VolumeStatusSnapshot` 映射的 `VolumePresentation`。菜单栏入口不另行推导操作状态。
- 关键 Interface：
  - 采用“事件输入、语义效果输出”的状态机接口；变更效果只能由协调器原子核对、领取并调用一次。
  - 所有变更操作携带操作 ID；所有磁盘证据携带物理磁盘 ID 与介质代次。
  - 操作 ID 由单一协调器内部生成，UI 不得提供或复用。
  - 卷实例由卷 ID、物理盘 ID 与介质代次组成；任何变更效果都绑定完整实例。
  - 用户动作也携带完整卷实例；设置检查或 actor 重入后必须再次核对，禁止旧点击绑定到重插后的新介质。
  - 数据卷声明只表达固定语义，绑定当前 observation session/revision、完整卷/整盘实例、精确
    sibling identity 集合和一次性请求；重插、重订阅、应用重启、拓扑变化或消费后失效。
  - 声明批准只证明当前请求的人类策略输入已核对，不生成 `VolumeSnapshot`，不替代健康、挂载、
    依赖、后端或物理盘事实。
  - helper 只接受结构化动作和磁盘标识，不接受任意 shell 字符串。
- 数据或 API 契约：
  - 写入只允许从新的完整安全快照产生。
  - 命令返回成功仅触发复核，不直接改变为最终成功状态。
  - 过期操作、错误卷、错误介质代次和不完整观察结果一律忽略或失败关闭。
  - 默认 `norecover`，不使用 `allow_other`、`remove_hiberfile` 或 force 选项。
  - 诊断只接受封闭状态/原因/结果码、数量、版本、布尔事实、时间/耗时、数值退出状态和运行期匿名别名；不记录卷标、用户名、BSD 名、磁盘或卷 UUID、任何路径或任何 stderr 文本。
- 架构约束：
  - macOS 15.4+，Apple Silicon first。
  - 默认且唯一 MVP 后端为 macFUSE FSKit。
  - 第一阶段要求用户单独安装官方 macFUSE；不静默安装依赖。
  - 应用启动后从系统实际状态重建，不信任上次缓存。
  - 一个物理磁盘同一时刻最多执行一个变更操作。
  - 执行器在系统调用前重新读取目标身份；与效果绑定实例不一致时执行零次变更。
  - 写路径在请求与每次变更前重新读取 Setup facts 和完整卷安全事实，并让完整卷事实成为系统调用前最后一次异步预检；整盘推出在请求与每次变更前读取完整、无重复且包含发起卷的 sibling inventory，并在实际推出前确认所有子卷仍未挂载。
  - 已领取的写入或推出变更发生超时、取消或介质事件时，整盘租约至少持续到真实进程退出；整盘卸载或最终推出即使明确失败也必须以新的完整物理盘事实收敛可能的部分卸载或重挂载，观察不完整则继续锁定。
  - 当前 operation 接纳的完整整盘事实原子更新全部 sibling；同代介质的移除记录单调不回退，同 operation 的迟到 `present` 也不得复活已移除卷；完整清单中缺失的发起卷不得提供重试。
  - 同一物理盘由另一卷持有租约时，UI 禁用该盘所有 sibling 的变更动作并明确提示勿读写或断开；整盘 absence 验证会原子撤销全部 sibling 状态。
  - 最终预检拒绝必须以零次系统变更结束操作、显示明确失败原因并释放未执行的整盘租约。
- 已接受的 ADR：
  - [ADR 0001](../adr/0001-read-only-system-observation-boundary.md) 固化实物 Gate 前的只读系统观察和不完整证据失败关闭边界。
  - [ADR 0002](../adr/0002-structured-one-shot-helper-boundary.md) 固化结构化、一次性 helper 消息边界；它不授权 IPC、安装、提权或真实磁盘执行。
  - [ADR 0003](../adr/0003-private-bounded-diagnostic-snapshots.md) 固化诊断持久化的字段白名单、私有文件、完整性核对和不得恢复运行状态边界。
  - [ADR 0004](../adr/0004-pin-macfuse-static-code-identity.md) 固化 macFUSE 所选精确版本同一批准条目中的
    requirement、Team ID、CodeDirectory identity 和同一 `SecStaticCode` secured Info.plist
    identifier/version 组合信任策略。
  - [ADR 0005](../adr/0005-separate-observed-volume-from-data-declaration.md) 固化只读 candidate 与
    当前连接一次性数据卷声明的分离，以及声明不是 System Evidence 的边界。
  - [ADR 0006](../adr/0006-scope-setup-conflict-evidence.md) 固化具名 Gate 2 候选范围、
    installed footprint 三态和环境基线必须同时完整的失败关闭语义。
  - [ADR 0007](../adr/0007-separate-bounded-gate-evidence.md) 固化正式 App 与有界 Gate 证据工具的
    只读依赖隔离、显式封存的 stop-and-drain/FIFO 顺序、最终 verified observation 前提和
    `readyForHumanReview` 不等于 Gate 通过的边界。

## 测试决策

以下内容是产品验收要求；它们归属哪个 Gate、是否已完成，只以[分阶段实施计划](../engineering/implementation-plan.md)为准。

- 关键路径：
  - 健康外置 NTFS：只读 → 标准卸载 → 新安全快照 → 安全参数挂载 → 实际可写验证。
  - 可写、只读或被禁止写入的卷：整盘标准卸载 → 所有子卷验证 → 标准推出 → 整盘消失验证。
- 边界行为：
  - 休眠、dirty、健康未知、内部/受保护卷、非 NTFS、介质代次变化。
  - unknown candidate 可见但零 mutation 资格；声明在重插、应用重启、睡醒重订阅、sibling
    拓扑变化、UUID 克隆但实例不符或重复消费后拒绝。
  - 多分区物理盘、重复点击、过期回调、错误操作 ID 和应用重启恢复。
  - 运行中拔盘、同设备名重新插入、旧代次回调晚到和 inventory 重建。
  - 错误卷、错误后端、仍为只读或非法挂载点不得进入“可写”。
- 异常行为：
  - 设备忙、权限失败、依赖缺失、冲突驱动、引擎退出、超时、睡眠唤醒和中途拔盘。
  - 任何失败都不得产生强制卸载、自动恢复或自动可写挂载效果。
  - 推出回调成功但磁盘仍存在时，不得显示“可以拔出”。
- 发布前验证：
  - 可牺牲磁盘与 NTFS 镜像覆盖创建、覆盖、追加、重命名、删除、Unicode 和大量小文件。
  - 连续挂载、卸载至少 100 次。
  - Windows `chkdsk` 后无新增错误，内容哈希一致。
  - dirty 与休眠卷写入阻断测试 100% 通过。
  - macOS 15.4 与当前稳定 macOS 分别实机验证。

## 风险与开放问题

- NTFS-3G 与 macFUSE FSKit 缺少完整官方兼容矩阵，必须满足[分阶段实施计划](../engineering/implementation-plan.md)中的对应 Gate 后才能进入真实数据盘路径。
- FSKit 后端的性能、卸载稳定性和部分文件语义仍需实机验证。
- Disk Arbitration 只读观察和静态代码身份读取已有软件原型；尚未验证的是真实变更 adapter、
  原始设备授权、生产签名、公证、沙盒与权限组合。
- 用户仍可能误把外置 Windows 系统盘声明为数据盘。当前连接声明只能防止自动误分类和旧判断
  复用，不能消除人为误认；若这一残余风险不可接受，产品必须永久保持只读。
- NTFS-3G GPL 和 macFUSE 再分发条款会影响未来打包；个人原型与公开分发必须分开决策。
- macFUSE、NTFS-3G 的版本固定、校验和和更新策略需要建立供应链记录。
- 若 FSKit 无法达到安全发布门槛，MVP 应停止，而不是自动降级到内核扩展方案。

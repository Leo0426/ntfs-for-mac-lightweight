# 修复 FSKit 可见范围导致的写入误拒绝：设计提案

日期：2026-09-30。状态：approved（2026-09-30 用户明确要求实现）。范围：修正正式 helper 的运行时预检，保留所有物理介质资格检查。

## 目标与实证

用户目标是在 macOS 中通过正式应用写入已授权的外置 NTFS 数据卷。
重启后 0.1.2（3）的 v2 helper 已注册、运行，固定签名的随机 challenge XPC 核验通过。
用户确认按类别中的 macFUSE（local）仍开启。对受信 vendor 的扩展组件执行官方局部重登记后，
PlugInKit 可见两个正式模块，但普通用户签名 FSClient 仍未观察到它们；安装件的固定用户
`fskit-ready` 子进程退出 1。

同一登录用户执行现有 ADR 0009 一次性镜像协调器，固定镜像种子与候选摘要通过；实际
FSKit local 可写挂载、挂载来源与驱动持有镜像核对、标准卸载、驱动退出、卸载后健康查询
全部通过，前后物理测试盘状态一致。本轮没有变更物理盘，没有测试文件写删或 Windows 复核。
当前枚举硬门禁会拒绝此实际可用场景，是软件缺陷。它不是用户没有批准 helper 或没有开启扩展。

卷外证据：原工作区 `.build/write-validation/context-probe-5cs1g91y/`。
该证据仅属本次独立镜像实验，不赋予正式应用以后请求的变更资格。

## 方案比较

1. **建议：每次写入请求先验证独立一次性镜像。**
   使用安装件内固定摘要、签名封印的空白 NTFS 种子，新建独占副本；由正式 helper 启动
   同一受信驱动、同一永久降权 UID/GID 与固定 FSKit local 参数。核对真实可写挂载与
   镜像归属后标准卸载，确认驱动被回收、挂载不存在，再判定运行时通过。
   约需临时 128 MiB 空间与数秒；支持无跨 Team 枚举可见性的环境，并在操作物理盘前拒绝
   真正不可用或收尾不完整的后端。
2. 保留目前 FSClient 正信号门禁：不会解决已复现的误拒绝；不建议。
3. 直接移除后端预检，只对物理盘尝试挂载：后端失败会使原生只读卷先被卸载；不采用。

## 建议方案的安全边界

- FSClient 查询仅作诊断，空结果不得描述为扩展未安装、禁用或后端可用。
- 镜像种子固定摘要，属于受保护安装清单与签名资源；不接受 UI 提供路径、镜像或参数。
- 每次独占创建副本，绑定路径、描述符、owner、mode、无链接、inode、大小与摘要。
  只允许该临时文件和本次独有挂载点，不能把 `/dev/disk…` 作为探针存储输入。
- helper 保持驱动句柄，独立核对稳定挂载表、FSKit 虚拟来源、固定驱动身份和对副本的持有。
  命令返回或单独的驱动日志不算挂载成功。
- 正常和异常路径共同收尾：只在确认本轮归属时标准卸载；没有强制卸载、进程强杀或 kext 回退。
  不确定时保留驱动、文件与检查资格，关闭后续写入，并提供明确诊断。不能用超时或取消释放资格。
- 只有镜像可写、标准卸载和驱动退出均被确认后才报告通过。结果不缓存到以后请求。
- 探针结束后原有执行器重新核对物理目标、精确同盘分区集合、IOMedia 代次和挂载事实；
  启动扇区、UUID、休眠/dirty 健康与一次性角色声明检查保持原有要求。
- Windows 复核与 Gate 状态仍独立；镜像通过不算实盘写入通过。

## 实施与验收范围

新增纯逻辑探针协调器与 helper 内固定镜像适配器；更新受保护清单、构建与安装包核验。
先 RED 再 GREEN：覆盖实际挂载成功而 FSClient 不可见、缺失/禁用后端、错误归属、启动失败、
标准卸载失败、驱动退出未确认、并发/重复请求与取消收尾。
运行仓库全部检查、严格 Release、只读边界和安装包负例，完成正式安装件镜像闭环。
随后 fresh 核对已授权 NTFSLAB，完成正式 helper 写入、写删与标准推出；Windows 复核单列。

## 来源与限制

- [Apple FSClient](https://developer.apple.com/documentation/fskit/fsclient) 与本机 Xcode 27 SDK：
  描述枚举接口，未保证当前调用者一定能看到其他 Team 的模块。
- 本仓库 ADR 0009 的现有镜像协调器与当日实际证据；旧实验候选通过不等于新版签名安装件通过。
- 本方案已进入实现和安装验收；每次正式写入仍必须获得新的镜像闭环及物理目标证据。

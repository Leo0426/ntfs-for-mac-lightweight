# 保证多卷物理盘的展示与辅助功能选择可区分

Status: resolved
Labels: bug, resolved
Assignee: Codex
Blocked-by:

## 问题

同一物理盘上的不同卷可以拥有完全相同的 `displayName`、挂载状态和详情。原展示层把卷名原样
用于侧栏、窄版 Picker、详情标题和 VoiceOver 公告；两个同名 sibling 因而无法由文字区分。
应用同时只监听派生后的公告字符串，若正文相同，从一个卷切换到另一个卷不会产生
`onChange` 事件。这会使当前选择不可靠，也不能作为未来 Gate 4 变更确认的前置展示契约。

## 验收

- 多卷物理盘的每个 sibling 取得确定、从 1 开始并与展示次序一致的本地序号前缀。
- 反转系统输入顺序不改变展示次序或序号；单卷物理盘保持原卷名。
- 生成标题彼此唯一，即使某个用户卷名与旧的生成后缀文字完全相同；完整长卷名仍保留。
- 展示序号不包含 UUID、BSD 名、路径或持久身份，也不参与授权判断。
- 侧栏、窄版 Picker、详情标题与 VoiceOver 公告统一消费同一个展示标题。
- 辅助功能变化键包含完整 `ReadOnlyDashboardSelection`；即使公告正文相同，不同卷选择仍是
  不同事件。
- 严格 Release、正式 App 构建和只读边界检查通过；不执行任何真实磁盘变更。

## 评论

2026-08-31：UI 自动证据审计发现该问题。修复前的 Release 行为检查稳定失败于“同名 sibling
必须获得隐私安全的本地序号”；第二个 RED 编译检查证明展示层没有结构化公告事件接口。

## Resolution

2026-08-31：第一版仅为完全同名组追加“· 卷 N”，独立复核用用户卷名
`A · 卷 1` 证明生成标题仍可碰撞；新增反例后 CoreChecks 再次 RED。最终展示层先按现有稳定
名称/完整实例身份排序，再为多卷物理盘的每个 sibling 生成唯一“卷 N · 原卷名”前缀；单卷
物理盘保持原名。正式 SwiftUI 的四个消费面因此使用同一可辨识标题。

新增 `ReadOnlyAccessibilityAnnouncementEvent`，以选择身份和朗读正文共同参与相等性；主窗口
监听该事件并只把固定正文提交给系统公告。行为检查覆盖反转输入、长名保持、UUID/BSD 隐私和
相同正文下不同选择事件。该修复只补自动展示前置条件；320 pt、视觉、键盘、焦点和真实
VoiceOver 顺序仍须 Issue 13 人工验收。

严格 Release CoreChecks、完整 warnings-as-errors 构建、只读源码/依赖边界、本地 App 正向验包
和 5 组篡改包负向 fixture 全部通过。本地 ad-hoc App 版本仍为 `0.1.0 (1)`，主程序 SHA-256 为
`666860a8ca660d6f2b0e69c165df3f715e0d0c3538f5df314b9e6643ae349f27`；它不构成 Developer ID、
公证、Gate 5 或人工 UI 证据。全程未执行挂载、卸载、推出、修复、格式化或写盘。

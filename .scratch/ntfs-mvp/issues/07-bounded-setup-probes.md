# 让 Setup 探针在所有子进程行为下有界收敛

Status: resolved
Labels: bug, resolved
Assignee:
Blocked-by:

## 问题

创建本 Issue 时，固定命令超时后仍等待输出管道 EOF；若后代继承写端，读取任务可能超过
声明的超时。

## 验收

- 超时、取消和输出超限都在固定上界内返回。
- 确认直接进程退出后才返回，不留下当前探针进程。
- 关闭或遗失管道时返回固定失败，不泄漏输出文本到诊断。
- 不把 runner 扩展为任意命令接口。

## Resolution

2026-08-31：固定命令 runner 现在分别监督直接进程、输出上限和 deadline；输出超限、取消、
继承管道、关闭读端和终止未确认都在固定墙钟上界内失败关闭，且只有确认直接进程退出后才
返回普通完成。完整 Release 行为检查与只读边界检查已通过，runner 仍不是任意命令接口。

2026-09-08 仓库审查修正：原继承管道 fixture 只验证时间上界，并错误地接受 `.exited(0)`。
直接进程退出不能证明输出完整；现在 stdout 和 stderr 必须都读到 EOF，才允许返回普通退出。
固定排空窗口内未取得 EOF 使用 `outputUnreadable`，超时、超限和终止未确认仍保留更优先的
失败原因。已先强化原回归断言复现 RED，再记录两个读端的 EOF 完成 GREEN。
